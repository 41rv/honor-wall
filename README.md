# مسار — مساحة لإنجازك

تطبيق عربي شخصي يعمل على الجهاز لإدارة المشاريع ذات المراحل والخطوات المتداخلة، والمهام المستقلة، والأفكار. React + TypeScript + Vite + Tailwind CSS، وIndexedDB عبر Dexie، وPWA. لا خلفية ولا حساب ولا مزامنة ولا خدمات AI. استُبدل قالب Scrolling Nav بالتطبيق؛ المواصفات الأصلية محفوظة في [requirements.md](requirements.md).

## التثبيت والتشغيل على الكمبيوتر

يتطلب Node.js 22.12+ أو 24+؛ اختُبر باستخدام Node 24.19.0 وnpm 11.9.0.

```sh
npm ci
npm run dev
```

افتح عنوان خادم Vite الذي يظهر في الطرفية (المنفذ الافتراضي 5173). لتجربة النسخة النهائية بما فيها PWA:

```sh
npm run build
npm run preview -- --port 4173
```

ناتج البناء في `build/`. تحميل النسخة النهائية مرة واحدة ثم إعادة تحميلها يتيح سيطرة Service Worker والعمل دون إنترنت. لا تعتمد على خادم التطوير لاختبار PWA. لا تنشر المشروع مباشرة كملفات TypeScript؛ انشر محتويات `build/`.

في هذه البيئة السحابية استخدم `npm ci --cache /tmp/honor-wall-npm-cache` عند الحاجة لأن مجلد cache الافتراضي قد لا يكون قابلًا للكتابة. لا تحتاج إلى مجلد عمل Git إضافي؛ المهام السحابية معزولة أصلًا.

## الاستخدام

- التنقل: الرئيسية، المشاريع، المهام، الأفكار، التقدم. أول بطاقة في الرئيسية لالتقاط فكرة بعنوان ووصف اختياري، ثم اختصار «أكمل من حيث توقفت»، وخطوة تنفيذ واحدة لكل مشروع نشط والمهام المستقلة المتبقية. الإضافة السريعة متاحة دائمًا على الهاتف.
- أنشئ مشروعًا، ثم مراحل وخطوات. افتح أي فرع لإضافة خطوات فرعية بلا حد ثابت للعمق، أو لتعديل اسمه وملاحظاته. أسهم الرفع والخفض تعيد ترتيب الأشقاء ويُحسب الترقيم تلقائيًا. يمكنك طي الفروع، وتُستعاد وضعية تمرير المشروع عند الرجوع من التفاصيل.
- تبدأ العناصر بـ«لم تبدأ»، ويمكن بدء العمل أو الإكمال. حالة الآباء ذوي الأبناء تُستنتج من الخطوات النهائية. علامة الإتمام متاحة مباشرة بجانب كل خطوة ومرحلة، وفي التفاصيل. إتمام فرع يكمل جميع عناصره النهائية داخل معاملة واحدة؛ وإعادة فتحه تعيدها إلى «لم تبدأ» مع حفظ سجل الإنجازات السابق. المرحلة الفارغة لا تُحسب كمهمة.
- يُتمّ المشروع تلقائيًا عند اكتمال جميع خطواته النهائية بنسبة 100%. يبقى زر «إتمام المشروع» متاحًا لإتمامه يدويًا قبل ذلك دون تغيير حالات خطواته أو النسبة. المشروع الفارغ لا يُتمّ تلقائيًا. يمكنك إلغاء الأرشفة وإعادة الفتح والحذف بعد تأكيد ثم التراجع.
- قسم المنجزات في صفحة المهام مستقل وقابل للطي ويعرض الإنشاء والإنجاز والمدة، مرتّبًا من الأحدث. لا تُحذف المنجزات تلقائيًا.
- تحويل فكرة إلى مشروع أو مهمة يتطلب تأكيدًا، ينسخ العنوان والوصف ويحفظ الفكرة الأصلية مؤرشفة. الأفكار لا تُحتسب ضمن المهام.
- البحث شامل للأسماء والملاحظات، وتفتح النتيجة تفاصيل العنصر مباشرة.
- الملاحظات تظهر فورًا أثناء الكتابة، وتُحفظ مسودة استعادة محلية. الكتابة السريعة تُجمع في حفظ متتابع بعد 250 مللي ثانية دون توقف، مع تفريغ الحفظ فور الخروج من الحقل أو التنقل أو التصدير أو تحديث التطبيق. فشل الحفظ يبقي المسودة وإجراء إعادة الحفظ، ويظهر تحذير عند مغادرة الصفحة وفيها تعديل غير محفوظ. عند استيراد نسخة تُزال مسودات الاستعادة السابقة لتجنب خلط البيانات.

## الحسابات والتواريخ

- نسبة المشروع/الفرع = عدد الخطوات النهائية المكتملة ÷ عدد الخطوات النهائية. الآباء لا يُحسبون مرة ثانية؛ غياب الخطوات يعرض رسالة بدل نسبة.
- الألوان: أقل من 25% رمادي، 25–49% برتقالي، 50–74% أزرق، 75–99% تركوازي، 100% أخضر. يظهر العدد والنص الرقمي أيضًا.
- صفحة التقدم تعرض مجموع المشاريع (بما فيها المؤرشفة)، النشطة (غير المغلقة وغير المؤرشفة)، والمغلقة (بما فيها المؤرشفة). تعرض أيضًا أعدادًا منفصلة للمهام المستقلة والخطوات النهائية غير المكتملة في جميع المشاريع.
- إنجازات آخر 7 أيام نافذة متحركة من الوقت الحالي إلى 168 ساعة مضت. يُحتسب كل عنصر مرة واحدة إذا كان **مكتملًا حاليًا** وتاريخ إنجازه الحالي داخل النافذة؛ المراحل والآباء مستبعدون.
- عند إعادة فتح مهمة/خطوة، يُمسح `completedAt` الحالي. تحتفظ الأحداث بكل الإكمالات السابقة وإعادة الفتح. الإكمال الجديد يمنح تاريخًا جديدًا دون مضاعفة العدّ. `startedAt` يحفظ أول بدء عمل صريح؛ `createdAt` لا يتغير. عند إغلاق المشروع يكون `completedAt` تاريخ الإغلاق، ويُمسح عند إعادة فتحه. بدء أول خطوة يثبت بدء المشروع.
- التواريخ ISO 8601 UTC في قاعدة البيانات، وتُعرض بالعربية حسب المنطقة الزمنية للجهاز. المدة هي الأيام الكاملة المنقضية من الإنشاء إلى الإنجاز، لا ساعات العمل الفعلية ولا أيام التقويم الشاملة للطرفين.

## حفظ البيانات والنسخ الاحتياطي

قاعدة البيانات `masar-v1` بإصدار بنية Dexie 2 (الإصدار الأصلي 20). أُبقي تعريف 1، وأضيف جدول `taskCycles` وفهرس التكرار دون إعادة كتابة الصفوف القديمة أو تغيير المعرفات. النسخة الاحتياطية الجديدة v2 تشمل الدورات، واستعادة v1 القديمة مدعومة. الترحيلات المستقبلية تُضاف فوق الإصدارين دون حذف قاعدة المستخدمين. المعرفات ثابتة وفريدة، وعمليات العلاقات متعددة الجداول تعمل داخل معاملات ذرية.

صفحة النسخ الاحتياطي متاحة من أيقونة التنزيل أعلى التطبيق. تصدير JSON يشمل المشاريع والمراحل والخطوات والمهام والأفكار والملاحظات وسجل الأحداث. الاستيراد يتحقق من الإصدار والحقول والتواريخ والمعرفات وترتيب الأشقاء وعلاقات الآباء والمشاريع والدورات، ويعرض معاينة وتحذيرًا قبل التأكيد. الاستبدال يتم في معاملة واحدة؛ الفشل يتراجع بالكامل. الأحداث قد تشير إلى عناصر حُذفت، عمدًا للاحتفاظ بتاريخها.

**حذف بيانات الموقع/التطبيق قد يمحو IndexedDB**. حذف سجل التصفح وحده لا يمحوها عادةً. صدّر نسخة دورية واحتفظ بها في مكان خاص. البيانات مرتبطة بأصل الموقع (البروتوكول والنطاق والمنفذ)، وليست مشتركة تلقائيًا بين خادم التطوير والمعاينة أو بين الكمبيوتر والهاتف. لتغيير الأصل، صدّر ثم استورد. لا توجد Google Drive أو مزامنة سحابية.

الخط العربي Tajawal مضمّن ضمن حزمة التطبيق ويعمل دون إنترنت؛ ترخيصه في `public/fonts/Tajawal-LICENSE.txt`. الأيقونات من Lucide.

## تثبيت واقعي على أندرويد دون استضافة مدفوعة

1. نفّذ `npm ci` ثم `npm run build` على الكمبيوتر.
2. التطبيق منشور على https://41rv.github.io/honor-wall/. لاستضافة نسخة مستقلة، يمكنك إنشاء مشروع **Cloudflare Pages / Direct Upload** ورفع محتويات مجلد `build/`. لا تحتاج إلى خدمة خلفية.
3. افتح نطاق HTTPS الناتج على Chrome في أندرويد، وانتظر اكتمال التحميل، ثم أعد الفتح. من قائمة Chrome اختر «تثبيت التطبيق» أو «إضافة إلى الشاشة الرئيسية»، أو استخدم زر التثبيت إن ظهر في صفحة النسخ الاحتياطي.
4. افتح التطبيق المثبت مرة متصلًا ثم جرّبه دون إنترنت. يلزم الاتصال فقط لتنزيل النسخة أول مرة والتحديثات.

بديل: أي استضافة مجانية للملفات الثابتة تعطي HTTPS وتخدم التطبيق من جذر النطاق. ضبط التطبيق الافتراضي يفترض المسار `/`. للنشر على صفحات GitHub تحت مسار المستودع استخدم `VITE_BASE_PATH=/honor-wall/ npm run build`؛ هذا يضبط ملفات التطبيق وروابط الأيقونات وmanifest وService Worker معًا.

عناوين loopback على الكمبيوتر تُعد بيئة موثوقة لاختبار PWA، لكن فتح عنوان الشبكة المحلية للكمبيوتر عبر **HTTP** من الهاتف ليس بيئة موثوقة ولا يضمن إتاحة التثبيت. لا تعطّل تحقق TLS لتجاوز ذلك. التثبيت الفعلي على هاتف أندرويد لم يُختبر في هذه البيئة.

## الاختبارات

```sh
npm test                 # منطق الحسابات والبيانات عبر IndexedDB محاكى
npm run lint            # فحص الشيفرة ومنع التحذيرات
npm run build            # TypeScript وبناء الإنتاج وService Worker
npm run test:e2e         # اختبارات المتصفح على بناء الإنتاج
```

اختبارات Playwright تستخدم Chromium النظامي إن وُجد؛ وإلا ثبّته أولًا بواسطة `npx playwright install chromium`. ثم ابنِ التطبيق قبل الاختبارات. الاختبارات تعمل على أصل منفصل وقواعد بيانات متصفح مؤقتة، ولا تلمس بياناتك الشخصية.

تم اختبار: مرحلتين/عشر خطوات (30% و100%)، الإتمام التلقائي عند 100% والإتمام اليدوي قبلها، إعادة الترتيب، الإغلاق وإعادة الفتح والإحصائيات، حفظ الملاحظات والبحث والعودة، أحداث إعادة الإكمال والعدّ الفريد، تحويل الأفكار، الحذف والتراجع، النسخ الاحتياطي ورفض العلاقات المكسورة والتراجع عن فشل الكتابة، بقاء البيانات بعد إعادة الفتح، الشاشات بعرض 320 بكسل والوضعين، المشاريع الطويلة والتفرع العميق واستعادة التمرير، وأصول PWA والقراءة/الحفظ وإعادة التحميل دون إنترنت.

لا يشمل التحقق: التثبيت على جهاز أندرويد حقيقي أو iOS/Safari. لا يمكن ضمان التخزين إذا مسح المستخدم بيانات الموقع أو أزالها المتصفح تحت ضغط مساحة الجهاز؛ النسخ الاحتياطي اليدوي هو وسيلة الاستعادة.

## الملفات

- `app/model.ts`: الأنواع والحسابات والتحقق من النسخ والبحث والتواريخ.
- `app/db.ts`: قاعدة Dexie والمعاملات والإنشاء والحالات والتحويل والحذف والاستيراد.
- `app/App.tsx`: صفحات التطبيق وتفاصيل العناصر والنماذج والتنقل والحفظ التلقائي.
- `app/styles.css`: التصميم المتجاوب والوضعان وإمكانية الوصول.
- `vite.config.ts`: البناء وTailwind وPWA والتخزين المؤقت للأصول المحلية.
- `tests/`: اختبارات المنطق وقبول المتصفح.

نجحت سبع مجموعات تفاعل من ملفات الموقع الفعلية: اليوم والتقويم والداشبورد والرؤى والسجل والإضافة الموحدة وRTL والنسخ والاستعادة. نقل الفحص العام كل استجابة عبر curl مع تحقق TLS ثم مررها إلى Chromium؛ المتصفح لا يثق بشهادة وسيط البيئة. لم يُعطل التحقق. اختُبر تحديث PWA وإعادة الفتح دون اتصال على نسخة الإنتاج في ملف معزول. حدود الفحوص موضحة في تقرير النشر.

للتحديثات التالية ابنِ التطبيق بالأمر `VITE_BASE_PATH=/honor-wall/ npm run build`، ثم انشر محتويات `build/` فقط مع ملف `.nojekyll` إلى فرع النشر، بعد الاختبار. لا ترفع نسخ بيانات المستخدم الشخصية إلى المستودع.

## تحسين الاستجابة — الإصدار 1.0.1

عولجت إعادة إنشاء الأزرار خلال الضغط، وقراءة سجل الأحداث كاملًا مع كل تعديل، وتكرار حساب الفروع، والحفظ المنفصل لكل حرف. أصبحت قائمة المهام والمشاريع والشجرة مكونات ثابتة، والحسابات مفهرسة مرة لكل تحديث للخطوات، والكتابات محددة بالجداول والأسلاف المتأثرين فقط. مساحة زر الإتمام 44 × 44 بكسل، ويظهر أثر الضغط فورًا، وتُفتح المنجزات بعد نجاح الحفظ، ويُعاد الزر لحالته السابقة عند الفشل.

نتائج التحقق المفصلة في [تقرير الاختبارات](docs/VALIDATION.md). التحديث لا يغير اسم قاعدة البيانات أو إصدارها ولا يحذف بيانات المستخدم. النسخة المثبتة سابقًا قد تحتاج إلى فتح صفحة النسخ الاحتياطي والضغط على «تطبيق التحديث المتاح». لا تمسح بيانات الموقع للحصول على التحديث.

## التقاط الأفكار والإتمام السريع — الإصدار 1.0.2

أصبحت خانة الفكرة أول بطاقة في الرئيسية وتحتها لوحة التقدم، مع حفظ مباشر بزر الإدخال أو «حفظ الفكرة» دون التنقل إلى قائمة الأفكار. المسودة تبقى عند فشل الحفظ أو التنقل، ولا يُعلن نجاح التسجيل إلا بعد اكتمال معاملة التخزين. قائمة الأفكار تعرض 30 بطاقة أولًا، مع «عرض المزيد»؛ النص الكامل محفوظ ويمكن فتحه في التفاصيل. الإضافة الجديدة تلغي البحث وتعود إلى الأفكار المفتوحة، حتى لا تُحفظ فكرة وتختفي خلف نتائج البحث أو الأرشيف.

أزرار إتمام واضحة للخطوة والمرحلة والمشروع في القوائم والتفاصيل. إتمام المرحلة/الفرع يكمل خطواته النهائية، مع تحديث الحالات والنسب والتواريخ والآباء في معاملة ذرية واحدة. أضيف زر إتمام المشروع يدويًا، ثم أضيف الإتمام التلقائي عند 100% في الإصدار 1.0.3. المراحل الفارغة قابلة للإتمام دون احتسابها مهام أو اختراع نسبة تقدم.

نجحت 25 اختبارات للحسابات والمعاملات والحفظ، و25 محاكاة متصفح. اختبار حفظ فكرة مع 2000 فكرة قائمة ومعالج أبطأ أربع مرات اكتمل في نحو 446 مللي ثانية، بما فيه العودة من الأرشيف وإلغاء البحث. هذه نتيجة محاكاة وليست ضمانًا لزمن جهاز بعينه.

## الإتمام التلقائي — الإصدار 1.0.3

حسب توضيح المستخدم الأحدث، يُتمّ المشروع تلقائيًا عند اكتمال جميع خطواته النهائية. هذا يُحدّث بند المواصفات الأصلية الذي كان يفصل 100% عن إغلاق المشروع؛ بقي ملف المواصفات الأصلي محفوظًا. تُطبّق القاعدة عند إتمام خطوة أو مرحلة، وعند حذف خطوة إذا أصبحت جميع الخطوات الباقية مكتملة، وكذلك على المشاريع المكتملة في البيانات السابقة عند فتح التطبيق أو استيراد نسخة.

تحديث حالة المشروع وتاريخه وسجل الإغلاق يتم في معاملة الخطوات نفسها، دون تكرار حدث الإغلاق. لا تُحتسب المراحل الفارغة ولا يُستخدم التقريب لإعلان الاكتمال. يبقى زر الإتمام اليدوي متاحًا قبل 100% دون تعديل الخطوات. إعادة فتح المشروع متاحة؛ إذا ظلّت خطواته كلها مكتملة، تُطبّق قاعدة الإتمام التلقائي مجددًا عند فتح التطبيق. لا يُفتح مشروع مغلق تلقائيًا عند إعادة فتح خطوة، حفاظًا على الإتمام اليدوي.

## التدقيق الشامل — الإصدار 1.0.4

أُصلحت ضياع تعديلات الاسم عند التنقل، وضغط الإتمام المتكرر أثناء الحفظ، وتكرار التراجع، والتحقق من تواريخ التقويم وعلاقات النسخ العميقة والمعرفات الخاصة. حُسّنت رسائل أخطاء التخزين بالعربية، والتركيز داخل النوافذ وبعد نقل المهمة للمنجزة، والتباين وأهداف اللمس والتفاف النصوص واستعادة موضع المشروع الطويل. بقيت قاعدة البيانات وبيانات النسخة السابقة كما هي.

نجحت 41 حالة بيانات و38 حالة متصفح، و140 حالة عرض في الوضعين على خمسة أحجام، مع 44 صورة قبل التحسين و44 بعده. فتح مشروع من 500 خطوة تحسن من 179.5 إلى 52.7 مللي ثانية كوسيط ثلاث عينات على بيئة الاختبار. هذه القياسات لا تضمن أداء جهاز معين؛ التقرير يسجل أيضًا التفاوت والقيود والاختبارات غير المتاحة.

يمكن إعادة فحص الأداء والصور بعد `npm run build` بواسطة `node scripts/qa-performance.mjs after` و`node scripts/qa-visual.mjs after`. لتجربة تحديث PWA استخدم `node scripts/qa-pwa.mjs <new-build> <old-build> <base-path>`، مع بنايتين محفوظتين بالمسار نفسه؛ الاختبار يستخدم ملف متصفح مؤقتًا وبيانات تجريبية.


## تجربة التنفيذ والثيمات — الإصدار 1.0.5

تعرض بطاقة المشروع المرحلة الحالية والخطوة النهائية المقترحة وإتمامها مباشرة. يُقدم «جارٍ العمل» الأحدث تعديلًا، ثم ترتيب المشروع. عند الإتمام يظهر الاقتراح التالي، وتبقى آخر خطوة مكتملة متاحة لإعادة فتحها. تعرض الرئيسية أربع بطاقات مشاريع أولًا مع «عرض المزيد»، وخمس مهام مع «عرض كل المهام»، وتحتفظ بالتقاط الأفكار في المقدمة. الإحصائيات التفصيلية في صفحة التقدم.

«أكمل من حيث توقفت» يعيدك إلى آخر خطوة فتحتها أو عملت عليها، ويحفظ مرجعها على الجهاز. إذا اكتملت أو حُذفت أو أُرشف مشروعها، يختار خطوة جارية ثم أول غير مكتملة من المشاريع النشطة. الاختصار للتنقل، ولا يُحتسب التزامًا إضافيًا.

زر ⋯ والضغط المطوّل يفتحان إجراءات المشاريع والمراحل والخطوات والمهام والأفكار. تتحول القائمة إلى لوحة سفلية على الهاتف؛ الحركة والتمرير يلغيان الضغط المطوّل، والحذف يستخدم التأكيد والتراجع الحاليين.

من أيقونة لوحة الألوان في أعلى التطبيق اختر **أخضر** أو **أبيض وأسود**، ثم **فاتح** أو **داكن** أو **اتباع النظام** بصورة مستقلة. يُحفظ الاختيار محليًا، وتبقى أشرطة التقدم مصحوبة بالأعداد والنسب. نتائج الاختبارات والصور والقياسات في [UX_REPORT.md](UX_REPORT.md).

لإعادة الفحص بعد `npm run build`: `node scripts/ux-visual.mjs after` للثيمات الأربعة وخمسة أحجام، و`node scripts/ux-performance.mjs after` للأداء. اختبار تحديث النسخة السابقة مع بقاء البيانات والاستكمال والمظهر: `node scripts/ux-pwa.mjs <new-build> <old-build> <base-path>`، باستخدام ملف متصفح مؤقت وبيانات تجريبية فقط.

يُحفظ طلب الإتمام المعلّق مؤقتًا قبل كتابة IndexedDB ويُستعاد بعد التحديث الفوري. تُزال المسودة بعد انتهاء الكتابة أو الفشل المعلن، ولا تُعيد إنشاء عنصر محذوف. تبقى البيانات الأساسية والتواريخ والسجل في IndexedDB.

## استيراد مشروع من ChatGPT

من «المشاريع» اختر «استيراد مشروع»، ثم «اختيار ملف JSON» وارفع الملف وراجع المعاينة قبل التأكيد. تضيف العملية مشروعًا مستقلًا بمراحله وخطواته المتداخلة وملاحظاته داخل معاملة واحدة، وتحافظ على البيانات السابقة. استخدم [PROJECT_IMPORT_SPEC.md](PROJECT_IMPORT_SPEC.md) مع ChatGPT، أو ابدأ من [المثال الجاهز](examples/project-import.json). هذا الخيار منفصل عن استبدال البيانات بنسخة احتياطية. اختبارات الصيغة في [PROJECT_IMPORT_REPORT.md](PROJECT_IMPORT_REPORT.md)، وقياسات فتح الواجهة في [PROJECT_IMPORT_PERFORMANCE_REPORT.md](PROJECT_IMPORT_PERFORMANCE_REPORT.md).

## المهام والجدولة — الإصدار 1.0.8

المهمة العامة بلا موعد افتراضيًا. من نموذج الإضافة أو «تعديل الموعد والأولوية» يمكن تحديد تاريخ ووقت اختياري، أو تكرار يومي/أسبوعي بأيام/شهري بيوم. تتاح فترة الاقتراب ٠/١/٣/٧ أيام، وأولويات أيزنهاور الأربع كشريط صغير. في الشهر القصير يُستخدم آخر يوم بدل إسقاط الموعد.

إنجاز المتكررة يخص الدورة الحالية فقط، وهي متاحة حتى الموعد التالي؛ اليومية تنتهي منتصف الليل. تُحفظ المكتملة والفائتة في سجل تفاصيل المهمة، وتظهر مهمة واحدة في القائمة. تعديل التكرار يحفظ التاريخ ويطبق مراجعة جديدة. منطقة الجدول تُحفظ كما كانت عند إنشائه، ويظهر اسمها داخل النموذج؛ إلغاء الجدول وإعادة إنشائه يتبنى منطقة الجهاز الجديدة عند الحاجة.

نجحت ١١٥ حالة بيانات ومنطق و٨٠ حالة متصفح، ومقارنة الترحيل وبقاء الجداول الستة والدورات بعد إعادة فتح المتصفح دون إنترنت. [التقرير والاختبارات والسياسات والقيود](TASKS_REPORT.md). لا يتغير استيراد `masar.project` الإصدار 1.
